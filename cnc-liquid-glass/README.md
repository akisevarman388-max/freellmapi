# ЧПУ 2в1 — моушн-ролик в стиле Apple Liquid Glass

Вертикальный ролик 1080×1920, 34 с, 30 fps. Собран целиком кодом: HyperFrames + three.js, без After Effects,
без ключей и без GSAP-анимаций. Всё, что в кадре, считается функцией от времени `render(t)`.

Готовый файл: `out/video.mp4`.

## Как запустить

```bash
cd cnc-liquid-glass
npx -y hyperframes preview                       # студия-превью в браузере
npx -y hyperframes snapshot --at 0.4,3.8,11,16,24,33   # контрольные кадры в PNG
npx -y hyperframes check                         # lint + рантайм + раскладка + контраст
npx -y hyperframes render . -o out/video.mp4 -q delivery --fps 30
```

Рендер идёт в WebGL; без видеокарты (SwiftShader на 4 ядрах) занимает около часа.

## Сюжет

| Время | Сцена | Что происходит |
| --- | --- | --- |
| 0–6,8 с | Хук | Стеклянная «2» влетает из глубины с ударом (вспышка + тряска). «Два станка?» — цифра переворачивается в «1» на слове «Нет.». Затем «1» пролетает сквозь камеру. |
| 6,8–22 с | Станок в стеклянном кубе | Куб летит на зрителя по линии взгляда, камера облетает его. Фрезер ведёт контур (стружка), шпиндель уходит, на его место защёлкивается лазерный модуль (вспышка + тряска). Лазер гравирует «2в1» и вырезает плашку (искры, свечение). Камера отъезжает, куб уходит вверх «хлыстом». |
| 22–34 с | Финал | Стеклянный заголовок «2в1» поднимается снизу и садится с ударом, кнопка-призыв «Узнать цену» из стекла, нажатие со вспышкой. |

## Как устроено

**Привязка ко времени HyperFrames** (`index.html`, первый `<script>`):

- на `window.__timelines["main"]` регистрируется приостановленный GSAP-таймлайн с одним линейным
  твином `clock.t: 0 → 34`. Это только часы, ключей в нём нет. Его `onUpdate` вызывает `render(clock.t)`;
- слушатель `hf-seek` вызывает `render(e.detail.time)`. Оба пути сходятся в одной функции, повторный вызов
  для того же `t` пропускается, поэтому кадр рисуется один раз;
- сборка сцены (загрузка шрифта, PMREM, компиляция шейдеров) завершает промис
  `window.__hf.buildReady["main"]`; HyperFrames ждёт его перед первым кадром.

Нет `requestAnimationFrame`, таймеров, `Date.now()` и `Math.random()`. Частицы, стружка и искры
выводятся из `t` через хеш индекса, а холст с гравировкой каждый кадр перерисовывается с нуля по `t`.
Поэтому любой кадр можно отрисовать отдельно и в любом порядке.

**Стекло** — только `MeshPhysicalMaterial`, без прозрачности через opacity: `transmission: 1`,
`thickness` 0,9–1,5, `ior: 1.5`, `dispersion` 0,6–1,3 (радужные края), `clearcoat: 1`,
`attenuationColor` #B7A6FF / #7A5CFF. Геометрия скруглённая: куб и кнопка — `RoundedBoxGeometry`,
цифры и заголовок — `TextGeometry` из Inter Black (TTF с кириллицей) с фаской в 10 сегментов.
У букв лицевые грани плоские, а фаски сглажены.

**Окружение для отражений** — PMREM из отдельной сцены: тёмная фиолетовая сфера, светящиеся полосы
#7A5CFF и белого, верхний софтбокс, низкая фиолетовая полоса горизонта. Поворот окружения зависит от `t`,
поэтому блики «бегут» по стеклу.

**Фон** — полноэкранный шейдер за стеклом: почти чёрный #07050f и четыре медленно текущие светящиеся
ленты основного цвета. Ленты периодичны по вертикали, поэтому на «хлысте» фон уезжает бесшовно.
Стекло преломляет этот фон.

**Рендер**: ACESFilmic, sRGB.

**Титры** — HTML поверх WebGL, по 1–3 слова на стеклянной плашке: `backdrop-filter: blur`,
полупрозрачный белый градиент, светлая обводка, лаймовая точка-акцент. Тайминг каждой плашки берётся
из её `data-start`/`data-duration`: если сдвинуть клип в студии, появление и уход сдвинутся вместе с ним.
Плашки с `data-accent="1"` дают вспышку и короткую тряску камеры.

**Движение**: появления на outExpo / outBack, удары на outBack. Камера всё время слегка плывёт
(сумма медленных синусов), на акцентах трясётся с затуханием 0,13 с.

## Файлы

- `index.html` — вся композиция (сцена three.js, шейдер, титры, привязка ко времени).
- `assets/lib/` — three.js 0.184 (модуль + RoundedBox/Text/TTF/BufferGeometryUtils) и GSAP 3.15,
  лежат локально, рендер не ходит в сеть.
- `assets/fonts/` — Inter (SIL OFL, см. `OFL.txt`).
- `out/video.mp4` — готовый ролик.
- `REVIEW.md` — итоги проверки и что осталось улучшить.
